# cadenya — the Cadenya CLI

Command-line interface for the Cadenya API, generated by redwood over the
Go SDK.

## Install

```sh
go install go.cadenya.com/cadenya-cli@latest
```

(During development the module resolves the SDK via a local `replace`;
release builds pin a published SDK version.)

## Configuration

- `CADENYA_API_KEY` — API key (or `--api-key`)
- `CADENYA_WORKSPACE_ID` — default workspace-id for commands that take one
- `--base-url` / `CADENYA_BASE_URL` — override the API endpoint
- `cadenya --version` prints the binary release version plus the API contract version it was generated against

## Usage

```sh
cadenya api-keys list
cadenya api-keys retrieve <id>
cadenya api-keys create --metadata @metadata.json --spec @spec.json
```

Responses print as indented JSON. List commands print one page plus
`nextCursor`; pass `--cursor` to continue.

## Flag forms

Boolean flags take no space-separated value: `--include-info` enables,
`--include-info=false` disables explicitly (`--include-info false` is a
usage error — `false` would parse as a positional argument).

Repeatable flags (shown as `[--flag <value>]...` in the reference) take
one value per occurrence; comma splitting is disabled so values — JSON
documents especially — may contain commas:

```sh
cadenya tool-sets tools list --names a --names b
```

## JSON and secret input

Every JSON-valued flag accepts a literal document, `@path/to/file.json`,
or `-` to read stdin (`-` may be used by AT MOST ONE JSON argument per
invocation — stdin is a single document). Keep secrets out of shell
history. Repeatable JSON flags take one document per occurrence:

```sh
cadenya api-keys create --metadata @metadata.json --spec @spec.json
```

A repeatable JSON flag (shown `[--flag <JSON>]...` in the reference)
takes one document per occurrence.

## Streaming

```sh
cadenya objectives stream-events <objective-id>
# resume after a disconnect (an explicitly empty value clears the checkpoint):
cadenya objectives stream-events <objective-id> --last-event-id <id>
```

Streamed events are NDJSON: one compact JSON document per line, so each
stdout line parses independently (`jq -c`, line readers, `while read`).
Nothing but event JSON is written to stdout. Ctrl-C closes the connection
cleanly. Ordinary single-response commands keep indented JSON.

## Display modes

`--display json|table|extended` (root or per-command; json is ALWAYS the
default so scripts stay stable). `table` renders the configured columns via
aligned text for objects and list pages — a page shows only the current
page, with the next cursor reported on stderr so stdout rows stay clean.
`extended` prints the same columns as psql-style vertical records. Missing
or null values render `-`; embedded newlines/tabs are escaped; composite
values print compact JSON. Streaming commands accept only json (NDJSON);
commands with no applicable configured columns reject table/extended with
a usage error.

## Exit codes

- `0` success
- `1` API or transport error (message on stderr)
- `2` usage error (bad/missing arguments), before any network I/O
